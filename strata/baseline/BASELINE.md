## 八、为什么要盯着 PCIe 溢出（命中率分桶）

### 为什么要盯着 PCIe 溢出（命中率分桶）

| 指标 | 实测 |
| --- | --- |
| 溢出 0 → 0.5% 之间 | 231.8 → 141.4 tok/s（−39%） |
| 理论应有的掉速 | −6.6% |
| 同一 decode 数字可对应不同状态 | 141 tok/s 在溢出 0.5% 和 3% 时都出现过 |
| 剩余未覆盖专家 | 20.5%（约 5,046 槽） |

备注：

- **溢出 0 → 0.5% 之间**：断崖在这里，不是线性
- **理论应有的掉速**：实测 −39%，差 6 倍 → 成本在流水线气泡，不在带宽
- **同一 decode 数字可对应不同状态**：只报 decode 没有可比性，必须同时报溢出/命中率
- **剩余未覆盖专家**：这台机器上剩下的最大单点收益

## 九、工程常数（可直接套用）

```text
槽位数 = min(24576, (启动时空闲显存 − 884 MiB) / 1.318 MiB)
```

| 项 | 值 |
| --- | --- |
| 每个专家槽位 | 1.318 MiB |
| 固定预留 | 700 MiB（系统）+ 184 MiB（投机解码头）= 884 MiB |
| 槽位上限 | 24,576 = 48 层 × 512 专家 |
| 固定开销实测 | ≈5.9 GiB（6,045 / 5,927 MiB） |
| 每 GiB 专家缓存 | ≈ +6.5 tok/s（拟合斜率 6.53） |
| 拟合截距 | 91.9 tok/s |
| PCIe 溢出敏感度 | 1% 溢出 ≈ −39% decode |
| KV Cache（int8 / 32K） | ≈384 MiB |

### 显存 → 槽位对账（三行都取自引擎日志原文，误差 <0.04%）

| 启动时空闲 | 公式计算 | 实际槽位 | 对账 |
| --- | --- | --- | --- |
| 6.07 GiB = 6,215 MiB | (6,215 − 884) / 1.318 = 4,045 | 4,043 | ✅ |
| 8.31 GiB = 8,509 MiB | (8,509 − 884) / 1.318 = 5,786 | 5,784 | ✅ |
| 26.01 GiB = 26,634 MiB | (26,634 − 884) / 1.318 = 19,537 | 19,530 | ✅ |

## 十、三条一句话判断（换机器后先对照这三条）

1. 专家缓存覆盖 <30% → 瓶颈在显存，先腾卡再说别的。
2. 覆盖 >75% 但 decode 仍 <200 tok/s → 瓶颈在 PCIe 与单 slot，换平台或加卡。
3. 同一台机器上 decode 波动 >20% → 先看 PCIe 溢出率，不要先怀疑模型或参数。
